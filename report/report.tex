\section{Introduction: The Problem}

The \emph{diameter} of an undirected, unweighted graph $G=(V,E)$ is the maximum
shortest-path distance between any pair of vertices:
\[
\mathrm{diam}(G) = \max_{u,v \in V} d(u,v).
\]
Computing the diameter is a fundamental graph problem because it captures the
largest communication distance in a network and is useful in the analysis of
social networks, communication graphs, and large sparse systems.

The most direct exact approach is based on the all-pairs shortest path (APSP)
idea: compute the shortest path distance from every node to every other node,
and then take the maximum over all pairs. In an unweighted graph, this can be
done by running breadth-first search (BFS) from each vertex, giving a time cost
of $O(n(n+m))$, where $n = |V|$ and $m = |E|$. For large sparse graphs, this is
often too expensive in practice because it requires a BFS from every node.

\section{Algorithms Studied}

\subsection{Crescenzi: iFUB with 4-Sweep High-Degree Initialization}

The iFUB (\emph{iterative Fringe Upper Bound}) algorithm improves practical
diameter computation by first finding a strong lower bound using BFS sweeps and
then refining upper and lower bounds layer by layer from a central candidate
vertex. In this project, the starting node for the 4-Sweep procedure is chosen
as a high-degree vertex, which often gives a stronger initial lower bound in
practice.

\paragraph{Theoretical Complexity.}
Each BFS costs $O(n+m)$. The practical efficiency of iFUB comes from requiring
only a limited number of BFS traversals on many real-world sparse graphs.
However, in the worst case, the method may still perform many BFS traversals,
leading to a worst-case running time of $O(n(n+m))$.

% Explain the intuition of iFUB here:
% 1. use 4-Sweep to get a good starting lower bound,
% 2. choose a center-like node,
% 3. inspect fringe layers,
% 4. stop when the lower and upper bounds meet.

\begin{algorithm}[h]
\caption{iFUB with 4-Sweep High-Degree Initialization}
\KwIn{Connected unweighted graph $G=(V,E)$}
\KwOut{Diameter of $G$}

Choose a high-degree start vertex $r_1$\;
Run BFS from $r_1$ to get a farthest node $a_1$\;
Run BFS from $a_1$ to get a farthest node $b_1$\;
Set $r_2$ as the middle vertex of a shortest path from $a_1$ to $b_1$\;
Run BFS from $r_2$ to get a farthest node $a_2$\;
Run BFS from $a_2$ to get a farthest node $b_2$\;
Set $u$ as the middle vertex of a shortest path from $a_2$ to $b_2$\;
Initialize a lower bound using the best sweep eccentricity\;
Run BFS from $u$ to get level sets around $u$\;
Inspect fringe layers from the outside inward\;
For each node in the current fringe, compute eccentricity if needed\;
Update lower and upper bounds on the diameter\;
\If{lower bound equals upper bound}{
    return the diameter\;
}
\end{algorithm}

\subsection{Takes-Kosters: BoundingDiameters}

The Takes-Kosters algorithm maintains lower and upper bounds on the
eccentricities of candidate vertices and uses these bounds to prune vertices
that cannot improve the current diameter estimate. In our implementation, the
candidate selection strategy alternates between promising upper-bound and
lower-bound choices, with degree-based tie-breaking.

\paragraph{Theoretical Complexity.}
As with iFUB, each BFS costs $O(n+m)$. The algorithm can terminate much earlier
than the naive baseline when bounds tighten quickly, but in the worst case it
may still require many BFS traversals. Therefore, its worst-case running time is
also $O(n(n+m))$.

% Explain the intuition of BoundingDiameters here:
% 1. maintain candidate nodes,
% 2. store eccentricity lower/upper bounds,
% 3. run BFS from selected candidates,
% 4. update bounds using triangle-inequality-style reasoning,
% 5. prune nodes whose bounds can no longer affect the diameter.

\begin{algorithm}[h]
\caption{BoundingDiameters}
\KwIn{Connected unweighted graph $G=(V,E)$}
\KwOut{Diameter of $G$}

Initialize all vertices as candidates\;
Initialize eccentricity lower bounds and upper bounds for each candidate\;
Initialize global diameter lower and upper bounds\;
\While{candidates remain and the diameter bounds do not meet}{
    Select a candidate using the bound-based selection rule\;
    Run BFS from the selected candidate\;
    Compute its eccentricity\;
    Update the global diameter lower and upper bounds\;
    Update eccentricity bounds of all candidates using the BFS distances\;
    Remove candidates that can no longer improve the answer\;
}
Return the final diameter estimate\;
\end{algorithm}

\section{Results and Comparative Analysis}

\subsection{Comparison with the Exact Baseline}

The current report is based on the \texttt{large} benchmark profile, so the CSV
contains large synthetic graphs and the \texttt{facebook\_combined} graph, but
no exact-baseline rows. Therefore, this run is used mainly for scalability
analysis. In earlier smaller-profile runs, both algorithms matched the exact
diameter on all validated synthetic graphs, so the present comparison should be
read as a performance comparison between already validated implementations.

\subsection{Speed vs. Quality Tradeoff}

In the current large-profile run, the main tradeoff is computational cost, not
answer quality. The recorded lower and upper bounds coincide in the benchmark
output, so the comparison is dominated by runtime and BFS count.

On the synthetic benchmark set, Takes-Kosters was clearly faster overall.
Crescenzi required about $534.38$ seconds in total, while Takes-Kosters
required about $90.02$ seconds. The BFS counts show the same trend:
Crescenzi performed $82{,}437$ BFS traversals, whereas Takes-Kosters performed
$12{,}409$. Thus, Takes-Kosters achieved the same practical goal using far
fewer BFS explorations on large synthetic graphs.

\subsection{Effect of Graph Structure}

Graph structure had a clear effect on performance. Takes-Kosters was faster on
$4/5$ Barab\'asi-Albert graphs, $5/5$ Erd\H{o}s-R\'enyi graphs, and $5/5$
Watts-Strogatz graphs. It also used fewer BFS traversals on these families.

The Facebook graph showed the opposite behavior. On
\texttt{facebook\_combined}, both algorithms returned diameter $8$, but
Crescenzi finished in $0.029051$ seconds using only $5$ BFS traversals, while
Takes-Kosters needed $0.060778$ seconds and $10$ BFS traversals. This suggests
that Crescenzi's 4-Sweep high-degree initialization is especially effective on
this real-world graph.

\subsection{Discussion}

The results suggest that Takes-Kosters scales more gracefully on the large
synthetic families because its bound updates prune many candidates early and
reduce the number of BFS traversals. Crescenzi, however, performs very well
when a strong initialization quickly leads to tight bounds, which appears to be
the case on the Facebook graph. Overall, Takes-Kosters is the better choice for
the large synthetic benchmarks in this project, while Crescenzi is more
effective on the tested real-world Facebook graph.

\section{Conclusion}

This project compared Crescenzi's iFUB algorithm and the Takes-Kosters
BoundingDiameters algorithm for graph diameter computation on one real-world
graph and several synthetic graph families. The implementations behaved
correctly in earlier validated small-graph experiments, where both algorithms
matched the exact baseline. In the large-profile experiments used for the main
comparison, the focus was therefore on scalability and practical efficiency.

The main conclusion is that Takes-Kosters is faster in practice on the large
synthetic benchmark families and also uses fewer BFS traversals. It was faster
on most Barab\'asi-Albert graphs and on all tested Erd\H{o}s-R\'enyi and
Watts-Strogatz graphs, showing better scaling as graph size increases. This
indicates that its pruning-based strategy is effective on large sparse
synthetic networks.

At the same time, the Facebook graph produced a different outcome. Both
algorithms returned diameter $8$, but Crescenzi was faster and used only half
as many BFS traversals as Takes-Kosters. This shows that graph structure plays
an important role in practical performance, and that no single algorithm is
uniformly best for every graph family.

Overall, the experiments answer the main project questions clearly: Takes-Kosters
scales better and is usually faster on the synthetic families used here, while
Crescenzi performs especially well on the tested real-world graph. Future work
could include evaluating additional real-world datasets, extending the exact
validation set, and studying how different initialization or candidate-selection
strategies change the practical behavior of both algorithms.
